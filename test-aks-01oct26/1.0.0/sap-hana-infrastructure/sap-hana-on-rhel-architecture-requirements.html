SAP HANA on RHEL Architecture Requirements

Running SAP HANA on Red Hat Enterprise Linux (RHEL) requires strict adherence to certified configurations to ensure performance, stability, and supportability. This section outlines the architectural requirements and foundational considerations for deploying SAP HANA workloads.

Prerequisites and Supportability

Before initiating a deployment, it is critical to align the infrastructure with both Red Hat and SAP guidelines.

In official documentation, the term RHEL serves as a synonym for both RHEL for SAP HANA and RHEL for SAP Solutions. Always consult the Certified and Supported SAP HANA Hardware Directory to ensure your hardware choice is validated for your specific workload.

Hardware Certification

SAP HANA requires specific hardware profiles to handle high-memory throughput and low-latency storage requirements. * Certified Hardware: You must use servers, storage systems, and cloud instance types that are explicitly listed in the SAP HANA Hardware Directory. * Verification: For non-appliance scenarios, verify that your specific server model is compatible with your RHEL release using the Red Hat Hardware Compatibility List.

Deployment Models

Architectural requirements differ based on the deployment scale: * Scale-Up: A single-node environment where the database is contained within one server. * Scale-Out: A distributed environment where the database is partitioned across multiple nodes.

For both models, if implementing High Availability (HA), you must utilize the RHEL High Availability Add-On. Support for these environments follows the specific policies defined in the Support Policies for RHEL High Availability Clusters.

Hands-on Activity: Verifying System Readiness

This activity guides you through the process of verifying that your RHEL environment meets the basic criteria for an SAP HANA installation.

Prerequisites

  • An active RHEL for SAP Solutions subscription.

  • Root access to the target RHEL server.

Step 1: Check RHEL Subscription Type

Ensure your system is registered with the correct subscription, which provides access to the necessary repositories for SAP HANA.

# Verify the active subscription
subscription-manager list --consumed

Step 2: Validate Hardware Certification

Use the following command to retrieve your hardware vendor and product information to compare against the SAP HANA Hardware Directory:

# Retrieve hardware information
dmidecode -t system | grep -E "Manufacturer|Product"

Step 3: Check Repository Availability

Confirm that the SAP-specific repositories are enabled to access the necessary packages for SAP HANA optimizations.

# List enabled repositories for SAP
yum repolist | grep sap

If the repositories are missing, use subscription-manager repos --enable=rhel-sap-for-rhel-8-x86_64-rpms (adjust for your RHEL version) to enable the required channels.

Architectural Best Practices

  • Update Services: Leverage the Update Services for SAP Solutions (E4S). This allows you to stay on a specific RHEL minor release for an extended period, which is crucial for the lifecycle management of SAP HANA environments. Refer to the Red Hat support policy for Update Services for details.

  • HA Implementation: When designing for HA, ensure that your fencing mechanisms and resource agents are configured according to the Red Hat official documentation for SAP HANA clusters to prevent data corruption during failover events.
